# Правила работы в этом репозитории

- Перед добавлением или изменением иконки прочитайте `CONTRIBUTING.md`. Для архитектурных решений при наличии локального ТЗ смотрите `docs/private/ICON_PACK_SPEC.md`; этот каталог не входит в публичный репозиторий. Текущий исполнимый контракт находится в `scripts/icons.mjs`; если меняете формат, обновите валидатор, правила и предпросмотр вместе.
- Исходник рисунка — `icons/<name>.svg`, а имени и поиску соответствует `metadata/<name>.json`. Не редактируйте сгенерированные файлы как источник и не копируйте SVG из Lucide или других наборов без явного решения по лицензии и происхождению.
- Для рисунка используйте локальный skill `.agents/skills/draw-icon/SKILL.md`; для проверки набора или PR — `.agents/skills/review-icons/SKILL.md`.
- Для подготовки выпуска и проверки npm-архива используйте `.agents/skills/release-icons/SKILL.md`.
- После изменения исходников запускайте `bun run check`: он проверяет иконки и метаданные, Oxlint, форматирование Oxfmt, сборку и публичные типы React-пакета. Для исправления форматирования используйте `bun run format`. После изменения иконок дополнительно запускайте `bun run preview` и смотрите HTML-лист при 16, 20 и 24 px; автоматическая валидация не заменяет визуальное ревью.
- React-компоненты, типы и пакетные SVG создаются командой `bun run build` из исходников; `packages/react/dist` не редактируется и не коммитится.
- Когда иконка получает `ready` или меняется принятая иконка, обновляйте `CHANGELOG.md`. Черновики не записывайте как опубликованные. Версию и дату ставьте только в release PR.
- Перед изменением выпуска или workflow прочитайте `docs/RELEASING.md`. Тег `v0.1.0` предназначен для первого GitHub Release и исключён из npm workflow; остальные release-теги не создавайте, пока React-пакет, лицензия и npm Trusted Publisher не готовы.
- Не добавляйте комментарии в код. Перед коммитом проверьте `git diff --cached` и включайте только файлы задачи. Сообщение пишите коротко, на английском, одной строкой в формате `<type>: <summary>`. Не добавляйте описание, тело сообщения или любые трейлеры, включая `Co-Authored-By`. Пример для изменения валидатора: `fix: validate SVG paths`; для выпуска: `chore: prepare vX.Y.Z release`.
