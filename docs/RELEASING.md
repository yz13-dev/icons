# Выпуск `@yz13/icons`

Рабочий файл GitHub Actions — `.github/workflows/publish.yml`. При отправке тега `vX.Y.Z` в `yz13-dev/icons`, кроме `v0.1.0`, он проверяет, что коммит тега входит в историю `main`, сверяет версию `packages/react/package.json` и `CHANGELOG.md`, выполняет `bun run check` со сборкой пакета и проверкой типов, затем публикует его в npm через OIDC. Тег `v0.1.0` служит для первого GitHub Release и не запускает npm-публикацию. Для `main` и PR отдельный workflow `.github/workflows/check.yml` выполняет проверки и прикладывает HTML-предпросмотр; в PR изменённые иконки сравниваются с базовой веткой. При сборке корневой `LICENSE` копируется в пакет для включения в npm-архив. Выбрана лицензия MIT для кода и SVG. Первая версия пакета подготовлена к ручной публикации; после неё следующие версии сможет выпускать workflow.

## Первый выпуск

Для пакета, которого ещё нет в npm, сначала нужно создать запись в реестре. Настройка Trusted Publisher требует уже существующий пакет. Поэтому чистый OIDC workflow не может сам создать `@yz13/icons` с нуля.

Перед публикацией проверьте, что дата в `CHANGELOG.md` совпадает с фактической датой выпуска, и подтвердите правообладателя `yz13-dev` в `LICENSE`. Выполните `bun run check`, `bun run preview`, `node scripts/assert-release.mjs v0.1.0` и `npm pack --dry-run` из `packages/react`. Содержимое npm-архива и рисунки в предпросмотре должны быть проверены до публикации.

Первую версию владелец npm scope публикует вручную. Предпочтительный путь — с Node не ниже 22.14 и npm не ниже 11.15 выполнить в `packages/react` команду `npm stage publish --access public`, проверить архив и подтвердить staged-выпуск с 2FA на npmjs.com. Пакет станет виден с технической placeholder-версией уже после staging, но содержимое версии не будет доступно до подтверждения. Разовый выпуск можно провести и из отдельного workflow с токеном, но такой workflow требует временного npm credential и не использует Trusted Publisher для создания пакета. GitHub Release `v0.1.0` можно создать до публикации npm: его тег исключён из npm workflow.

После появления пакета откройте его настройки в npm и добавьте Trusted Publisher:

| Поле npm             | Значение       |
| -------------------- | -------------- |
| Provider             | GitHub Actions |
| Organization or user | `yz13-dev`     |
| Repository           | `icons`        |
| Workflow filename    | `publish.yml`  |
| Environment          | пусто          |
| Allowed action       | `npm publish`  |

Создавайте эту настройку незадолго до первого OIDC-выпуска: новая связь должна успешно опубликовать версию в течение двух дней, иначе истечёт. Для следующей версии подготовьте release PR, после его слияния поставьте тег на соответствующий коммит `main` и отправьте тег. Повторно тег начальной версии не отправляйте: npm не принимает публикацию уже существующей версии.

После проверки OIDC-выпуска можно запретить обычные токены в настройках публикации пакета. Workflow не содержит `NPM_TOKEN`; при публичных репозитории и пакете npm автоматически прикладывает provenance.

## Совместимость версий `0.x`

До `1.0.0` новые иконки и совместимые изменения получают следующую minor-версию, исправления рисунка или метаданных без изменения публичных имён — patch-версию. Удаление или переименование экспорта требует следующей minor-версии и явной записи о несовместимости в changelog. После `1.0.0` применяются обычные правила semver: несовместимые изменения требуют major-версии.
