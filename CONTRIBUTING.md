# Как добавить иконку

Правила ниже описывают текущий исходный формат и рисунок набора. Код, SVG и метаданные этого репозитория распространяются по [лицензии MIT](LICENSE).

## Исходные файлы

Для иконки `example` добавьте `icons/example.svg` и `metadata/example.json`. Имя — уникальный `kebab-case`, без номера версии. Используйте устойчивое название предмета или действия; вариант называйте по его отличию, а не `example-2`. Не редактируйте будущие сгенерированные React-файлы вручную.

Текущая схема метаданных:

```json
{
  "title": "Example",
  "category": "actions",
  "keywords": ["sample", "demo"],
  "status": "draft"
}
```

`title` — читаемое имя, `category` — один `kebab-case` идентификатор, `keywords` — непустые уникальные поисковые слова. `draft` означает рисунок на проверке; `ready` означает, что рисунок принят для следующего выпуска. Новые поля требуют изменения валидатора и публичного формата метаданных.

## Рисунок

- Предварительный ориентир — [правила Lucide](https://lucide.dev/contribute/icons/design-principles), но SVG создаётся для этого набора. Не переносите пути из чужого набора без отдельного решения по происхождению и лицензии.
- Холст 24×24, `viewBox="0 0 24 24"`, штрих 2 единицы, `currentColor`, круглые окончания и соединения. Корневой тег должен соответствовать существующим SVG в `icons/`.
- Оставляйте видимый штрих минимум в 1 единице от края. Между отдельными элементами оставляйте примерно 2 единицы, когда это не мешает узнаваемости. Сохраняйте сопоставимый оптический вес и убирайте детали, исчезающие при 16 px.
- Сейчас автоматический предпросмотр принимает только `<path d="..."/>` внутри SVG. Внешние ресурсы, фиксированные цвета, растровые изображения, скрипты, обработчики событий и `foreignObject` не допускаются. Поддержку новых безопасных SVG-элементов добавляйте в валидатор отдельным изменением.
- Автоматическая проверка проверяет синтаксис команд `path`, но не определяет узнаваемость, оптический вес, отступы и происхождение рисунка. Их проверяют глазами в предпросмотре рядом с другими иконками при 16, 20 и 24 px на светлом и тёмном фоне.

## Проверка и запись изменений

```sh
bun run check
bun run preview
```

Откройте `preview/index.html` и сравните новую иконку с соседними. При изменении существующего SVG используйте `bun run preview --base /путь/к/основной/ветке` для вида «до/после».

Сборка React-пакета берёт те же SVG и метаданные. После изменения исходников пересоберите `packages/react/dist`; сгенерированные файлы не редактируйте вручную.

Для принятой новой иконки добавьте её имя в раздел `Unreleased / Added` файла `CHANGELOG.md`. Исправление рисунка или метаданных запишите в `Unreleased / Changed`. Черновики перечисляйте отдельно и не включайте в выпущенную версию. В PR укажите назначение, отличия от близких иконок и происхождение рисунка. Предлагайте только работы, которые вправе передать для распространения по MIT; для сторонних материалов укажите автора, ссылку и лицензию.
